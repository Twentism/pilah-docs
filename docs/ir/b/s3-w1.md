## B7 · AI literacy

This week's B7 evidence is a different kind from the previous weeks'. Earlier
pages record what the tool got wrong and where I overruled it. This one records
the thing underneath that: **the written instructions the tool is made to work
under, and the documents I had to supply because they are not in the
repository.** Both are checkable by anyone, which is why they are linked rather
than described.

### The instructions the work is done under

The project does not use an AI assistant from a blank prompt. There are three
`AGENTS.md` files in version control, one per repository, and they are read at
the start of every session. All three are public and can be opened directly:

#### A deviation, argued rather than taken quietly

PIL-432 ships as two pull requests, and two branches cannot share one name. The
branch rule yields `feature/pil-432` for both, and the workspace file also says
*"Do not create an issue unless explicitly requested"*, which rules out
inventing a second Linear ticket to generate a second name. PR 1 was therefore
named `feature/pil-432-side-sheet`.

That is a deviation from a rule in the file, and it was put to the user as one
before the branch was created, not discovered afterwards. This is the part
worth more than the list above: an instruction file is only being used if a
case that does not fit it produces an argument instead of a silent exception.

### Where the instruction file itself was wrong

`AGENTS.md` is a work product, and two defects in it cost real time this week.
Both are in the mobile file.

- **It does not name the formatting gate that CI enforces.** Its validation
  section lists `flutter analyze` and `flutter test`. It says nothing about
  `dart format`, which
  [`.github/workflows/ci.yml`](https://github.com/bank-sampah-PILAH/pilah-mobile/blob/staging/.github/workflows/ci.yml)
  runs as `dart format --output=none --set-exit-if-changed lib test codegen`.
  PR 1's **first** CI run went red on exactly that. The cost was not the red
  tick: the formatting job sits upstream of SonarCloud in the same workflow, so
  the static-analysis evidence for the week did not run either, and for a while
  the pull request carried no quality-gate result at all. Fixed by
  [`5f3089bc`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/5f3089bc),
  a `style(design)` commit that exists only because the instruction file is
  incomplete. The gate now runs locally before every push whether the file
  mentions it or not.

- **The screenshot branch is spelled two different ways.** The file says
  `pr-<PR_NUMBER>-screenshots`, and about twenty branches in the repository use
  that hyphenated form. This week's three branches are `pr186-screenshots`,
  `pr195-screenshots` and `pr202-screenshots`, without the hyphen. The file was
  read and this detail of it was not followed. They cannot be corrected now,
  because the same clause says never to delete such a branch — renaming one
  breaks the images in a live pull request. So the deviation is recorded rather
  than repaired, and the next one uses the documented spelling.

  only**, decided while the slices were being planned rather than at commit
  time, because the guidelines reserve level 3 for a scan with a patch plan and

### Where it was wrong, and how it was caught

- **The plan's most load-bearing verified fact was stale by the time it was
  used.** The PIL-432 plan turned on seven cubits being provided above
  `MaterialApp.router`, verified by reading the file. Overnight, PIL-377
  replaced Bloc with Riverpod and the `MultiBlocProvider` ceased to exist. The
  conclusion survived — `ProviderScope` still wraps the router, so a
  root-navigator route still sees every provider — but it survived by luck, not
  by method. The user caught it and said so: *"wait so why the plan's biggest
  verified fact was stale?"* A fact verified on day one and used on day two has
  to be re-verified, especially in a repository where `staging` moved forty
  commits in two days.

- **A test seam that production could not use.** The platform was first
  injected into `SideSheetPresentation.resolve` through an
  `@visibleForTesting isWebOverride` parameter. That annotation means precisely
  *production must not pass this*, while `kIsWeb` being a compile-time constant
  means production is exactly what has to pass it. The project's existing idiom
  was already the plain explicit argument, in `NavigationForm.resolve`. Fixed
  in
  [`c9d3be17`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/c9d3be17)
  to a plain optional `isWeb` defaulting to `kIsWeb`. The annotation read as
  the tidy, disciplined choice and was a back door.

- **A claim in the pull request body that the browser disproved.** PR 1
  justifies its container with "a real route: Esc, browser back and
  `Navigator.pop` all close it". Driving the built app showed browser back does
  not close it, and does something worse: a `showGeneralDialog` route on the
  root navigator creates no history entry at all — `history.length` stayed at
  4 and the URL never changed — so back popped the page *underneath*, the shell
  navigated from the dashboard to the login screen, and the half-typed setoran
  was gone. The claim was already sitting in a pull request awaiting review.
  Two commits were needed, because the first fix only moved the problem:
  [`7655eacc`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/7655eacc)
  made the panel a declared route, so back closes the panel instead of the
  page, and back still skipped the discard guard, because `PopScope` is only
  consulted by `Navigator.maybePop` while a history traversal removes the page
  declaratively.
  [`9bbee7d7`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/9bbee7d7)
  closes it with `GoRoute.onExit`. Both halves were measured on screen with the
  dirty state visible, not reasoned about.

- **A test that could pass while proving nothing.** The platform gate has a
  native case and a web case. Under the Dart VM, `isWeb: false` and *no
  plumbing at all* are indistinguishable, so the native test would have passed
  against a version where the argument was never threaded through. The wide
  **web** case is the one that pins the wiring; the native case only guards the
  gate. Both are kept, and which one is doing the work is now written down.

- **A superseded CI run read as a failure.** Two pushes in quick succession
  leave two workflow runs against one pull request, and
  `gh pr view --json statusCheckRollup` lists jobs from both. The older run's
  jobs show `SKIPPED` because the newer run cancelled them, and read mid-flight
  that looked like SonarCloud being suppressed by the stacked base. It was not;
  Sonar ran and passed on both pull requests. Reading a rollup instead of the
  newest run is the same mistake as reading a green tick instead of the issue
  count.

- **A build reported as blocked that was not.** An earlier week recorded the
  Android debug APK as unbuildable on this machine. It builds. `JAVA_HOME`
  pointed at an Adoptium **JRE**, which carries no compiler, while a real JDK
  21 was installed alongside it; prefixing the build with the JDK path works.
  That is a correction of my own earlier claim, and it matters because the
  claim had been used as a reason to skip native verification.

- **A checklist I wrote that named the wrong tool.** The hand-off commands for
  the user's own terminal said `dart` and `flutter` bare. On this machine those
  resolve to a second, older Flutter install — Dart 3.9.2 against the 3.11.1
  the project needs — and the failure blames a package rather than the
  toolchain, so it reads as a dependency problem. The user hit it. Instructions
  handed to a person now carry the full SDK path.

- **Two findings from the review on PIL-436, both taken.** The claim that the
  Pengumuman feature stayed restorable was too narrow: the feature's own test
  suites guard its *pages*, but the **route-level** guards went out with the
  builders — the detail row fallback, the form's argument fallback, and the
  `keanggotaan_id` without which a nasabah belonging to two banks gets a 422 —
  along with the two tests that pinned them. Fixed in
  [`b6058f2a`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/b6058f2a),
  which keeps those three routes compiled and tested but unregistered, and
  builds the redirect locks by looping that same list so the locked paths
  cannot drift from the real ones. The second finding was about framing: the
  Nasabah removal had been justified by handover scoping when the parent
  acceptance criterion settles it directly and is role-neutral. The pull
  request body was corrected and credits the reviewer.

- **Screenshots missing from a pull request body, reported by a teammate
  rather than noticed.** Relayed by the user: *"he added that you haven't put
  the playwright screenshots in the PR description!!"* The mobile `AGENTS.md`
  requires them for user-visible web changes. The rule was in the file, the
  file had been read, and the step was skipped anyway.

### What I brought that the tool could not

The decision to put the setoran form in a side sheet is not in this list,
because it came from the ticket. What is in it:

- **Stacked pull requests instead of two sequential ones.** The plan agreed on
  29 October was PR 1, merge, then PR 2 from `staging`. The user overrode it
  after being shown the recorded costs — SonarCloud measuring both diffs as new
  code, and a retarget rebasing the second branch — and chose stacking anyway,
  so review of PR 2 could start while PR 1 waited on a human. Both predicted
  costs were checked afterwards, and the Sonar one did not reproduce in this
  repository.
- **The challenge to splitting a one-line fix into its own pull request**:
  *"why did you left real bug on purpose? That sounds shady since why do we
  need to create a whole new PR just for that small one line fix?"* Asking what
  a process rule is actually buying is not something the tool volunteers.
- **Redirects instead of deletions for PIL-436**, decided item by item. The
  ticket's own scope says delete the `/pengumuman*` routes, and the router
  registers no `errorBuilder`, so deleting them answers an old bookmark with a
  visible "page not found" — which the parent requirement forbids as firmly as
  it forbids the page. The user's call, given as a numbered list, was redirect
  the routes and remove the other two items.
- **The insistence on a physical device.** There is no staging release to
  install, so the alternatives were a debug build over a connection or nothing.
  The user set up wireless debugging and ran the checks on real hardware, which
  is what the instruction file asks for and what every previous week's page
  lists under *what is not finished*.

The running tally of corrections by cause, across every week, is in
[Part B](../part-b.md#b7-how-i-use-ai). That tally is the level-4 argument,
because the criterion's top level asks for AI use "managed based on data (notes
or metrics)" rather than on anecdote. This week adds to two rows that already
existed — a conclusion reached without the one check that would settle it, and
a claim stronger than its evidence — and it **closes** one entry rather than
adding to it, since the Android build turned out never to have been blocked.

## What is not finished

Stated here rather than left to look complete:

- **B1 to B6 are not claimed on this page.** PIL-432's two pull requests were
  still open at the end of the week and PIL-436's evidence is held with them,
  so none of it is reported yet. That is a reporting decision, not an absence
  of work.
- **Neither PIL-432 pull request is merged.** PR 1 has one approval, green CI
  and every review thread resolved; it is held open by an earlier
  changes-requested review that was never withdrawn after its findings were
  fixed. PR 2 is stacked on it and was awaiting its first review.
- **PR 2 has not been retargeted to `staging`.** It will be rebased when PR 1
  merges, so its commit hashes are deliberately not quoted anywhere in these
  docs yet.
- **The `AGENTS.md` formatting gap is recorded here and not yet fixed in the
  file.** The repair is one line in the mobile file's validation section naming
  `dart format --output=none --set-exit-if-changed lib test codegen`. Writing
  this page is what made it concrete enough to do.
- **Escape is untested in the browser, and is not reported as broken.**
  Synthetic key events do not reach the Flutter canvas in the automation
  harness — the control is that they do nothing to a pre-existing dialog
  either — so Esc is covered by a widget test and by nothing on screen.
- **A residual history quirk in the side sheet.** Closing the panel normally
  pushes a new history entry instead of consuming the one that opened it, so a
  back press after closing re-opens an empty panel. It is not data loss, it is
  strictly better than what it replaced, and it is disclosed in the pull
  request body rather than fixed in a third round.
