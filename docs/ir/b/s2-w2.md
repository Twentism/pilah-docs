## A panel that outlived its window

PIL-339 shipped a rule: the jadwal form becomes a side panel **only** at
expanded widths, because at medium the panel is about 320 px and the form does
not fit. The rule was enforced where the form opens, and nowhere else.

A container chosen at open time is not a container that stays correct. Resize
the window after opening and the panel survives into widths the open path
deliberately refuses:

| Starting state | Action | Before #125 |
|---|---|---|
| Panel open at 1440 px | shrink to 800 px (medium) | Panel stays, at a width the open path refuses |
| Panel open at 1440 px | shrink to 390 px (compact) | `MasterDetailLayout` drops the detail, but the page still believes a panel is open |
| After shrinking to compact | tap the add button | A sheet opens *and* a stale panel is still tracked |

The fix is one `didChangeDependencies` hook that closes the panel once the
window is no longer expanded, so *"the panel exists only at expanded"* holds at
all times rather than only at the moment the form is opened.

    which had already merged. Rather than fold it into the next feature branch,

### Positive, negative, corner

=== "Positive"

    [View](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/98589ec6)

    ```dart
    testWidgets('shrinking to medium closes the open panel rather than '
        'narrowing it', (tester) async {
      await _pumpAt(tester, const Size(1440, 900));
      await tester.tap(find.byTooltip('Buat Jadwal'));
      await tester.pumpAndSettle();
      expect(find.byKey(const ValueKey('jadwal-form')), findsOneWidget);

      tester.view.physicalSize = const Size(800, 900);
      await tester.pumpAndSettle();

      expect(
        find.byKey(const ValueKey('jadwal-form')),
        findsNothing,
        reason: 'a 2/5 panel at medium is the width the open path refuses',
      );
    });
    ```

    The `expect` before the resize is not decoration. Without it, a test that
    never opened the panel in the first place would pass the assertion that
    matters — the same vacuous-pass shape as a loop over an empty set.

=== "Negative"

    [View](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/537da76a)

    ```dart
    expect(
      find.byKey(const ValueKey('jadwal-form')),
      findsNothing,
      reason: 'a blank form reappearing on resize reads as a bug; the panel is '
          'closed, and reopening it is the user\'s call',
    );
    ```

    Widening back past the expanded breakpoint must **not** resurrect the panel.
    The easy wrong fix is to derive panel visibility from width alone, which
    makes every one of the positive tests pass and then pops a blank form open
    the moment somebody drags a window edge.

=== "Corner"

    [View](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/537da76a)

    ```dart
    testWidgets(
        'after shrinking, the add button gives a sheet and no stale panel',
        (tester) async {
      // … open at 1440, shrink to 390, tap the add button again
      expect(find.byKey(const ValueKey('jadwal-form')), findsOneWidget);
      expect(
        find.byType(BottomSheet),
        findsOneWidget,
        reason: 'the reopened form belongs in the container for the new width',
      );
    });
    ```

    The corner is the **transition**, not either end of it. Both widths behave
    correctly in isolation; the defect only exists in the sequence open → resize
    → reopen, where the page can hold a belief about a container that no longer
    exists.

### The defect that only a reviewer's timing could expose

[`077dd06e`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/077dd06e)
is the most interesting commit of the week, and it is a direct consequence of
the panel being a *longer-lived* container than the sheet it replaced.

A bottom sheet lives for one row: its `initialData` never changes. A panel does
not — selecting a different row refills the same form. So a save dispatched for
row A can return **after** the panel has moved to row B:

- `onSaved()` closes the panel the user is currently filling, losing unsaved
  input;
- a server field error attaches to a field that does not belong to it.

The fix is a generation counter, incremented whenever the panel switches rows:

```dart
final generasi = _generasiBaris;
// … await the request …
final barisMasihSama = generasi == _generasiBaris;
if (barisMasihSama) setState(() => _isSaving = false);
if (error == null) {
  if (barisMasihSama) widget.onSaved();
  AppNotification.showSuccess(context, …);   // the request did happen
}
```

Note what is *not* guarded: the success or failure notification still shows,
because the request really did occur and the user is entitled to know. Only the
parts that touch the now-foreign form are suppressed.

!!! important "Scallss found this in review, not a test"
    It was reported on PR #126 and is credited in the commit body. No test I
    had written could have caught it, because every one of them held the
    selection still. The class of bug — **an async result outliving the state
    that started it** — is the one a panel introduces and a sheet cannot have,
    and it is worth naming because the same shape will recur on every inline
    panel this project adds.

## B2 · Programming principles

### Single responsibility — the extraction that made the panel possible

**Principle: SRP.** Commit
[`0eab55fb`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/0eab55fb).

`JenisSampahForm` is extracted from `TambahJenisSampahBottomSheet`. The form
knows how to validate and save and nothing about where it sits; the sheet keeps
the chrome — corners, background, keyboard avoidance, the drag handle, and
**what "close" means**.

That last item is the whole point. The form never calls `context.pop()`,
because pop is correct for a sheet and wrong for a panel that sits inline in the
page body and closes by dropping the selection. Both containers are told through
the same `onSaved` callback instead.

The commit is behaviour-preserving: the sheet's existing tests are untouched and
still pass, including PIL-304's effective date, price summary and BR-03 warning,
which now live in the extracted form. That separation is what made the same form
reusable in a panel one commit later — the "helps when changes occur" the
criterion asks about, demonstrated rather than asserted.

!!! note "One extraction, two shapes of cost"
    The split also *created* the race fixed in
    [`077dd06e`](#the-defect-that-only-a-reviewers-timing-could-expose). A
    component reused across containers with different lifetimes inherits the
    longest of them, and the state it carries has to survive that. SRP made the
    reuse possible; it did not make the reuse free, and recording the second
    half is more useful than claiming only the first.

## B6 · Security

**Nothing is claimed for B6 this week, and that is the honest entry.**

PIL-338 is a layout-and-lifecycle ticket. It adds no route, changes no
permission, stores nothing new and renders nothing from untrusted input, so
none of its twelve commits carries an OWASP line. The weaker option — asserting
A01 because the page sits behind a Pengurus route — would be a claim the diff
cannot support, and a grader could knock it down in one question.

!!! warning "The remedy that was supposed to prevent this did not fire"
    After the OWASP item was missed twice, the
    [remedy adopted](../part-b.md#b7-how-i-use-ai) was to choose it **at
    slice-planning time**. For PIL-338 the right answer was "there is no claim
    here" — but that decision was never *recorded* at planning time, it was
    noticed afterwards. The remedy works when a slice has a claim; it does not
    yet capture the decision that a slice has none. Carried into
    [Sprint 2 · Week 3](s2-w3.md#b6-security), where every `green` commit names
    its item.

## B7 · AI literacy

### Where it was wrong, and how it was caught

- **A fix that created a new defect, found by a human and not by me.** The
  extraction in `0eab55fb` is clean and its tests pass. It also silently
  changed the form's lifetime from one row to many, which is what made a late
  save able to close another row's panel. Every test held the selection still,
  so the suite could not see it. Recorded in
  [`077dd06e`](https://github.com/bank-sampah-PILAH/pilah-mobile/commit/077dd06e)
  with the reporter credited.

- **A bug the existing tests were structurally blind to.** The bottom-sheet
  title overflow had gone unnoticed because *every* sheet test pumps at 800 px,
  where there is room to spare. The measurement is in the commit body — 49 px
  of overflow for "Tambah Jenis Sampah", 8.3 px for "Edit Jenis Sampah" —
  because "it overflows" is not a finding anyone can re-check.

- **A quality gate read as a result rather than a prompt.** The first push of
  #126 was green on CI with five open SonarCloud issues, which is the exact
  shape of the PR #70 lesson: the gate passes while issues remain. They were
  found by querying the issue count directly, not by reading the tick.

- **The OWASP decision was not recorded when it was made.** See
  [B6](#b6-security). The honest version is that no claim existed; the process
  failure is that nothing wrote that down until the week was being reported.

### What I brought that the tool could not

The judgement that #125 should be its own pull request. The defect was small,
the fix is one hook, and folding it into the PIL-338 branch would have been
less work — but then the defect and its fix disappear into a feature diff, and
a `[P2]` that arrived after its PR merged would have no visible answer. Keeping
them separate is what makes both legible.

Also the decision to restrict the panel to **expanded only**, matching jadwal,
rather than letting it appear at medium. At medium the panel is about 320 px
and this form holds a dropdown, a date picker, a price summary and the BR-03
warning. The rule is a product judgement about what fits, not something a test
could have derived.
